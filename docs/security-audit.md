## Reviewed boundaries

- The current app has no authentication, payment system, server mutation routes, server actions or private backend data. Public JSON/reference pages are authored static content. Browser-local XP, achievements and saved creations are editable by their owner; they must not become authoritative for competitive rewards or paid entitlements without server validation.
- All deployed `dangerouslySetInnerHTML` uses were reviewed. The theme initializer is fixed code and whitelists supported themes. JSON-LD uses `jsonLd`, which escapes `<` to prevent script-tag termination. User data is rendered through React text nodes. No application `eval`, `new Function`, `document.write` or user-controlled HTML assignment was found.
- Progress imports limit file/string size, validate the version and required shape, construct fresh whitelisted objects, normalize atomic numbers and clamp game/state values. `__proto__` keys are ignored rather than merged. Hostile titles remain literal text in the interface; SVG exports XML-escape titles, use fixed model geometry and have no script/event nodes. Malformed imports leave current progress intact.
- Current offline caching is same-origin GET content only; API, RSC transport and range requests bypass the worker. Navigation pages are bounded to 150 entries. No authenticated route exists. The worker is not an authentication boundary: private routes added later must explicitly bypass caching and respect private/no-store responses. Browser-local progress and caches are readable by any same-origin script, as expected for this account-free application.
- Query parameters choose whitelisted elements/games. External source URLs come from committed science data rather than imports. New-tab source links use `noreferrer` or `noopener noreferrer`. No user-selected remote image/fetch endpoint or SSRF sink was found.
- Actions are pinned to immutable commit SHAs, checkouts disable persistent credentials, and permissions are scoped per job. PR jobs receive no Vercel deployment credentials. No `pull_request_target`, untrusted artifact consumption or direct PR-data interpolation into shell commands was found. Production release uses the tested commit and prebuilt output after successful CI.
- Vercel CLI 62.2.0 is version-pinned but fetched separately with `pnpm dlx` during deployment. Its separately audited graph has unresolved advisories (SEC-06); the application-only audit cannot clear them. Both isolated CLI graphs were resolved without executing/installing CLI package code. Registry provenance and hosting-account access remain external supply-chain/account boundaries.
- Targeted secret-pattern checks found no credential-like tokens or private keys in current tracked text files or 209 reachable historical text blobs. Only `.env.example` is tracked. Live `/.env` and `/.git/config` returned 404. This is a heuristic scan, not verification that every possible secret format is absent.

## CSP compatibility and residual risk

Static Next.js hydration and the theme initializer use inline scripts, while Motion and React use inline styles. The policy deliberately retains `script-src 'unsafe-inline'` and `style-src 'unsafe-inline'` to preserve static rendering, offline operation and existing interactions. Production disallows `unsafe-eval`; development alone permits eval and WebSocket connections for Next.js tooling.

This policy restricts framing, plugins, base URLs, external scripts and off-origin fetches, but **does not prevent execution of an injected inline script**. Output escaping and trusted input boundaries remain necessary. A nonce/hash-only script policy would require a separately designed rendering/build strategy with offline and page-cache regression coverage. CSP is defense in depth, not evidence that XSS is impossible.

Public responses observed with `Access-Control-Allow-Origin: *` contain no authenticated/private data. That is acceptable for the current public reference dataset; reassess it if accounts or private endpoints are introduced.

## Verification

- Full application dependency audit after removal: zero known advisories in the locked runtime/development graph at audit time. This excludes the separately audited deployment CLI, which has the open SEC-06 findings. The production-only baseline audit also reported zero advisories.
- Lint, formatting, TypeScript, production build, all 26 learning unit tests and validation of all 118 scientific records passed locally.
- All 44 targeted mobile/desktop browser cases passed locally, including eight security cases. Browser regressions cover emitted headers on HTML/data/worker/fallback routes, actual CSP blocking of off-origin fetches and framing, and malicious backup content remaining inert in the UI and a parsed SVG document.
- Existing gameplay, onboarding, progress transfer, WebGL fallback and offline flows are checked against the production build under the new policy. Final CI and deployment evidence is available from the remediation commit's GitHub Actions runs.

## Access limitations and required account work

GitHub returned HTTP 403 for CodeQL alert listings, Dependabot alert listings and repository Actions permission settings. Their current alert state and default-token configuration could not be verified; a green workflow is not proof of an empty alert dashboard. Branch and production-environment reads succeeded and support SEC-02/03. No account settings or credentials were changed during this audit.

A maintainer should prioritize SEC-06 deployment-tooling remediation, and a repository administrator should resolve SEC-02/03, inspect those denied alert/settings pages, confirm secret scanning/private vulnerability reporting, and review Vercel project/team permissions and token scope. Vercel account, DNS/domain configuration and platform internals were not inspected. See [deployment setup](deployment.md) for concrete required checks and release settings.
